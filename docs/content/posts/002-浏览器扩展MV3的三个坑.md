# 浏览器扩展 Manifest V3 我踩过的三个坑

date: 2026-10-10
tags: 浏览器扩展, Manifest V3, 调试

开发「图提取」这个电商图片下载插件时，有三个坑各花了我不少时间。记下来，希望你别重复踩。

## 坑一：声明了 default_locale 却没有 _locales

我在 `manifest.json` 里写了：

```json
{
  "manifest_version": 3,
  "default_locale": "zh_CN"
}
```

结果浏览器**直接拒绝加载扩展**，弹出：

> 无法加载该扩展：Default locale was specified, but _locales subtree is missing.

原因很简单：`default_locale` 声明的是「我有国际化资源」，浏览器会去找 `_locales/zh_CN/messages.json`。文件不存在，整个扩展就不合法。

**结论**：要么老实建 `_locales` 目录 + `messages.json`，要么把这一行删掉。只想写中文界面的话，直接删掉最省事。

## 坑二：--load-extension 突然不生效了

自动化测试时我用命令行加载扩展：

```bash
msedge.exe --load-extension=F:\my-extension
```

以前能用，现在完全没反应，`Preferences` 里也查不到扩展记录。

原因：Chromium 129 之后把「命令行加载扩展」这个入口默认关掉了，对应的功能开关叫 `DisableLoadExtensionCommandLineSwitch`。手动加载页面（`chrome://extensions`）仍然正常，只有命令行方式被禁。

**解决办法**：把那个 feature 显式关掉即可：

```bash
msedge.exe --disable-features=DisableLoadExtensionCommandLineSwitch \
           --load-extension=F:\my-extension
```

## 坑三：截图工具拍到的是旧画面

这个是排查最久的。我用 DevTools Protocol 截图验证插件 UI：

```js
await client.send('Page.captureScreenshot', { format: 'png' });
```

问题来了：**页面上明明渲染正确，截出来的图却是发白的**。我一度怀疑是 CSS 透明度问题，把 `opacity`、`filter`、`mix-blend-mode` 全查了一遍，全是正常值。

最后靠对比四个环节的像素值才定位：

| 环节 | 像素值 | 结论 |
| --- | --- | --- |
| 磁盘源图 | `(37,99,235)` | 正常 |
| HTTP 响应字节 | `(37,99,235)` | 正常 |
| 页面内 canvas 读回 | `(37,99,235)` | 正常 |
| CDP 截图 | `(231,237,250)` | **不一致** |

也就是说，渲染管线是好的，**是截图接口拿到了陈旧的合成帧**。

**结论**：用 `captureScreenshot` 做视觉校验不可靠，尤其是图片刚加载完的时候。更稳的做法是：

- 用页面内 canvas 读回像素做数值断言（最可靠）
- 截图只用来做「有没有渲染出东西」的粗判

## 顺带一个经验

排查这类问题时，**控制变量比猜原因快得多**。我的做法是先搭一个自检页，把「页面脚本是否执行」「内容脚本是否注入」「按钮是否创建」「样式是否生效」四项分开打印，一眼就能看出卡在哪一环，比反复改代码试要快。

```js
lines.push('IGHosts 全局对象：' + (typeof window.IGHosts !== 'undefined'
  ? '存在（内容脚本已注入）' : '不存在（未注入）'));
```

## 小结

- `default_locale` 是「我声明了有 i18n」的意思，没建目录就别写
- Chromium 129+ 需要 `--disable-features=DisableLoadExtensionCommandLineSwitch`
- CDP 截图会拿到陈旧帧，视觉校验请用页面内 canvas 读回像素
